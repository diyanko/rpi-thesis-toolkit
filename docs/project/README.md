# Maintainer handbook

This folder is for the person who looks after the RPI Thesis Toolkit (an
unofficial, community-made project), and for
the AI coding agents that draft most changes. Students never need it, and it
is not included in the student ZIP. Every change is reviewed by a human
maintainer; the rules agents follow are in [AGENTS.md](../../AGENTS.md).

## What each file is for

| File | Use it when |
| --- | --- |
| [README.md](README.md) | You need the map: this page |
| [maintenance.md](maintenance.md) | You build, test, publish, update pinned tools, or review a requirement change |
| [style-guide.md](style-guide.md) | You write or review any text a student will read |
| [requirements.md](requirements.md) | You change formatting: each OGE rule, how the class meets it, differences from RPI's official LaTeX template, and open questions for OGE |
| [attribution.md](attribution.md) | You need to know what is ours and what is not (RPI's materials, the seal, third-party content), or prepare a release |
| `sources.json` | You record which OGE documents were reviewed, with dates and fingerprints |
| `upstream-files.json` | You compare your local copy of RPI's original template (`_local/legacy/`); `scripts/check.py` reads its hashes when that folder exists |

At the repository root, [AGENTS.md](../../AGENTS.md) holds the rules for AI
agents, and `CLAUDE.md` only points to it. Contributor-facing pages are
[CONTRIBUTING.md](../../CONTRIBUTING.md),
[CODE_OF_CONDUCT.md](../../CODE_OF_CONDUCT.md), and
[CREDITS.md](../../CREDITS.md) (people, sources, tools, and fonts).
`CITATION.cff` tells people how to cite the toolkit.

## Where things live

Everything is in one of four places. If a file fits none of them, ask before
adding it.

**Public source (tracked in Git, visible to everyone):**

| What | Where |
| --- | --- |
| Starter thesis files | `main.tex`, `metadata.tex`, `preamble.tex`, `references.bib`, `frontmatter/`, `chapters/`, `appendices/`, `figures/` |
| Formatting | `rpi-thesis.cls`; `assets/README.md` (how students download the seal; the seal itself is never committed) |
| Student guide | `docs/*.md`, diagrams in `docs/diagrams/`, printable sheet in `cheatsheet/` |
| Front-door pages | `README.md`, `CONTRIBUTING.md`, `CREDITS.md`, `CHANGELOG.md`, `LICENSE.md`, `CODE_OF_CONDUCT.md`, `CITATION.cff` |
| Maintainer handbook | `docs/project/` (this folder), `AGENTS.md`, `CLAUDE.md` |
| Website layout | `site/` (templates, CSS, fonts, artwork, `site.json` settings) |
| Scripts and CI | `scripts/`, `.github/workflows/`, `.github/` issue and pull request templates |
| Student editor settings | `.vscode/settings.json` and `.vscode/extensions.json` (shipped in the student ZIP) |

**Generated by scripts and CI (never tracked):** every `.html` page made from
Markdown, all PDFs, `build/` (compiled thesis), `dist/site/` (website and page
previews), and `dist/*.zip` (student starter, including its `START-HERE.html`).

**Local only (ignored by Git, never published):**

| What | Where |
| --- | --- |
| Personal notes, prototypes, sample outputs, agent scratch files | `_local/` |
| Downloaded OGE manuals and checklists | `_local/oge/` (read them from the official page; never commit or mirror them) |
| RPI's original LaTeX template, for comparison | `_local/legacy/` (download from RPI ITS's [Thesis Preparation page](https://itssc.rpi.edu/hc/en-us/articles/360010087512-Thesis-Preparation); `check.py` compares its hashes) |
| The RPI seal, for compiling the sample | `assets/rpi-seal.jpg` (ignored by Git; each student downloads it, see `assets/README.md`) |
| Agent and editor settings | `.claude/`, `.codex/`, `.idea/`, other files in `.vscode/` |
| Python environment and caches | `.venv/`, `__pycache__/` |

Agent configuration folders stay uncommitted: each maintainer's tools and
permissions are personal, and shared rules belong in `AGENTS.md`.

**Delete when you see it:** stray `.html` files next to Markdown, and PDFs or
LaTeX working files outside `build/`. Move anything personal into `_local/`.
`git status` should show only your intended changes.

## Yearly routine

Do this once a year, and whenever a student reports a concrete mismatch.

1. Open the OGE submission page linked in [requirements.md](requirements.md)
   and check for a new manual edition or checklist. Keep any downloaded copy
   in `_local/oge/`.
2. Review the new document against [requirements.md](requirements.md),
   section by section. Follow [Review a requirement change](maintenance.md#review-a-requirement-change).
3. Update `requirements.md` (rows, differences, and **Needs OGE
   confirmation**) and `sources.json` (title, edition, link, review date).
4. Change the class only where the evidence requires it, then run every gate
   in [AGENTS.md](../../AGENTS.md#verification-gates) and look at the PDFs.
5. Bump the version in the `\ProvidesClass` line of `rpi-thesis.cls`,
   following the [compatibility promise](maintenance.md#compatibility-promise).
6. Add a `CHANGELOG.md` entry that starts with **Changes your PDF?**
7. Update pinned tools ([Updating pinned tools](maintenance.md#updating-pinned-tools)).
8. Review the diff yourself. Publish only when you are sure and the
   [public-release checklist](maintenance.md#public-release-readiness) is
   complete, following [the website section](maintenance.md#the-website).

## Handoff checklist

When the project passes to the next maintainer:

- [ ] Transfer the repository or add the new maintainer with admin rights;
      update `site/site.json` if the repository or website address changes.
- [ ] Hand over the help and feedback form and its response sheet. The form's
      address lives only in `docs/troubleshooting.md` (section "Ask for help").
- [ ] Confirm that no RPI-owned files are tracked (`git ls-files`) and that
      the new maintainer knows the rule in [AGENTS.md](../../AGENTS.md#principles):
      link to RPI's pages; keep reference copies in `_local/`.
- [ ] Walk through this handbook, [AGENTS.md](../../AGENTS.md), and the
      [style guide](style-guide.md) together.
- [ ] Run the full [local verification](maintenance.md#local-verification)
      once on the new maintainer's computer.
- [ ] Review open issues and every `TODO(verify)` marker.
- [ ] Add the outgoing maintainer to [CREDITS.md](../../CREDITS.md#people),
      with their consent.
- [ ] Keep `_local/` personal: share any useful notes by adding them to this
      handbook, not by handing over the folder.
